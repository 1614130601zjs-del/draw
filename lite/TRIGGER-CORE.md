# 触发核心阶段记录

## 已实现

- `trigger-core.js`：纯逻辑解析完整 `image###提示词###` 标记，支持一条消息多个标记，并提供去标记后的可见文本。
- `index.js`：监听当前 SillyTavern 版本中存在的流式/消息更新/生成结束/swipe 事件；事件触发后做短延迟合并扫描。
- 普通聊天：扫描最新助手消息，按 chatId、消息索引、swipe id、标记偏移建立去重键；生成成功后将图片卡片插入该消息正文容器。
- 状态栏：扫描 `.shot-frame.scanning` 目标框，按提示词变化创建任务，并在同一框内显示图片卡片；卡片提供左右切换、滑动切换、再画一张和长按/右键保存。
- 生图请求：入口已区分 OpenAI 兼容接口与酒馆的 `/api/novelai/generate-image` 代理；记录保存在酒馆扩展设置中。
- 最新提交 `c10738d5b60a68f851e9ef411d271f54f585b6b9` 增强了 OpenAI 兼容接口图片响应的格式识别。

## 当前限制与风险

- 尚未在用户实际 SillyTavern 实例中运行验证；事件名称、DOM 选择器和状态栏容器结构可能因酒馆版本或正则布局不同而需要调整。
- NovelAI 当前复用酒馆已配置的代理连接，并非独立填写 NovelAI API Key/地址的完整配置页。
- 预设、角色库、完整提示词库、图片缓存画廊、内置世界书等完整模块尚未实现。
- 图片 data URL 暂时直接保存在扩展设置记录中，容量较大；尚未迁移到独立文件/IndexedDB 缓存。
- 状态栏候选图当前主要保存在该次 DOM 卡片实例中；页面刷新后的候选切换恢复尚未完成。
- 自动触发和回填已接线，但必须用用户实际的酒馆版本、OpenAI 兼容端点、NovelAI 配置和目标状态栏正则逐项实测，不能仅凭代码提交视为通过。

## 建议测试顺序

1. 刷新酒馆，确认扩展能加载且设置面板可见。
2. 在独立工作区用最简单提示词分别测试 OpenAI 兼容接口和 NovelAI 代理。
3. 普通聊天发送一条包含单个完整 `image###prompt###` 标记的助手输出，确认只发起一次请求、标记从可见正文移除、图片落在同一消息。
4. 测试同一消息多个标记、流式输出中 marker 分段到达、失败后点击重试、swipe 后再次生成。
5. 测试状态栏正则的 `.shot-frame.scanning` 是否真实存在，确认图片覆盖目标画框而不遮挡评论/弹幕/音乐。
6. 测试状态栏左右切换、再画一张、长按保存以及页面刷新后的行为。
